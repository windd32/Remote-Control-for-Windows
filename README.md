Минимальный WPF-прототип удалённого рабочего стола по прямому TCP-подключению. Управляющий ПК принимает входящее соединение; клиент показывает владельцу компьютера запрос согласия и передаёт экран и ввод мыши/клавиатуры только после подтверждения.

## Возможности

- Режим управляющего: слушает выбранный TCP-порт и показывает входящий рабочий стол.
- Режим клиента: подключается по IP и порту управляющего ПК.
- Передача экрана и управление начинаются только после нажатия «Да» на клиентском ПК.
- Закрытие окна клиента прекращает передачу.


Исполняемый файл появится в `RemoteControl\bin\Release\net8.0-windows\RemoteControl.exe`.
## Подключение
1. На управляющем ПК запустите программу, оставьте режим «Управляющий», укажите порт (по умолчанию `45831`) и нажмите «Начать ожидание».
2. Разрешите входящее подключение в брандмауэре Windows и перенаправьте выбранный TCP-порт на локальный адрес управляющего ПК в настройках роутера.
3. Передайте другу публичный IP управляющего ПК и порт. Друг выбирает «Клиент (этот ПК)», вводит адрес и нажимает «Подключиться».
4. Друг лично принимает запрос в окне на своём компьютере. При отказе управление не включается.
Для прямой связи публичный адрес и открытый порт нужны на стороне управляющего ПК. Серый IP клиента не мешает: клиент сам инициирует исходящее подключение. Если у управляющего CGNAT, понадобится публичный IPv6 или другая сетевая схема.
## Безопасность и ограничения
Это экспериментальный прототип, а не готовый защищённый продукт. Протокол не шифрует соединение и не выполняет надёжную аутентификацию; одноразовый код сессии не заменяет TLS. Не используйте через него недоверенные сети и не оставляйте порт открытым. Для реального использования нужны TLS с проверкой ключей, безопасное сопряжение устройств, обработка ошибок и аудит безопасности. Съём экрана ограничен основным монитором и уменьшенным разрешением. Некоторые защищённые окна Windows могут не отображаться.

Программа не скрывает подключение: клиенту показывается запрос и статус передачи экрана.
